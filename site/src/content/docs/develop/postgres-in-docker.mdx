## Goal

Run Postgres locally in a container and connect to it with `psql`, without installing
Postgres on your computer.

## Steps

### 1. The compose file

Both tracks use the same development database:

<Code code={devCompose} lang="yaml" title="infra/compose/dev.yml" />

- `postgres:18-alpine` is the same major version the VPS will run (lesson 3.3).
- `127.0.0.1:5432:5432` publishes the port to your computer only, not your network.
- The `pgdata` volume keeps the data when the container is recreated.
- The `healthcheck` lets `--wait` block until Postgres accepts connections.

### 2. Start it

From the repo root:

```bash
docker compose -f infra/compose/dev.yml up -d --wait
```

### 3. Connect with psql

`psql` is already inside the container, so you don't need it on your computer:

```bash
docker compose -f infra/compose/dev.yml exec postgres psql -U guestbook
```

Try `\l` (databases), `\dt` (tables; none yet) and `\q` to leave.

The backend connects with the URL from `backend/.env`:

```sh
DATABASE_URL=postgres://guestbook:guestbook@localhost:5432/guestbook
```

## Verify

```bash
docker compose -f infra/compose/dev.yml ps
docker compose -f infra/compose/dev.yml exec postgres psql -U guestbook -c '\dt'
```

The container is `Up (healthy)` and `psql` answers `Did not find any tables.`

:::tip[Port 5432 is taken?]
Another Postgres is already running on your computer. Stop it, or change the left side of
the port to `5433:5432` and the port in `DATABASE_URL` to match.
:::

## What you learned

A database in a container is disposable: same version as production, nothing installed on
your computer, and one command to wipe it and start over.

## Undo

```bash
docker compose -f infra/compose/dev.yml down      # stop, keep the data
docker compose -f infra/compose/dev.yml down -v   # stop and delete the data
```
