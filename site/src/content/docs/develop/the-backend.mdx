Write `GET /api/entries`, `POST /api/entries` and `GET /api/health`, and call them with
`curl`.

## Verify

With Postgres up and the API running, in a second terminal:

:::tip[Next.js track]
The commands are the same; `track` says `nextjs-fullstack-postgres`. The app folder is one
level higher, so the compose file is `../../infra/compose/dev.yml`.
:::

```bash
curl -i localhost:3000/api/health
```

```http
HTTP/1.1 200 OK
content-type: application/json
x-request-id: 523009b1-51fe-49cf-bbb3-0fa9af87c326

{"ok":true,"db":"up","track":"react-hono-postgres","env":"development","version":"dev"}
```

```bash
curl -s -X POST localhost:3000/api/entries \
  -H 'content-type: application/json' \
  -d '{"name":"  Ada ","message":"Hello"}'
curl -s localhost:3000/api/entries | jq
```

The `POST` answers `{"id":1,"name":"Ada","message":"Hello","createdAt":"…"}` (the spaces
around the name are trimmed), and the list contains it.

Now stop Postgres and ask again:

```bash
docker compose -f ../../../infra/compose/dev.yml stop
curl -s -w ' %{http_code}\n' localhost:3000/api/health
docker compose -f ../../../infra/compose/dev.yml start --wait
```

Health answers `{"ok":false,"db":"down",…} 503` while it is stopped and `200` again after.
The API itself never crashed.

## What you learned

An API is a few small routes plus the things around them: config validated once at startup,
one shared connection pool, and a health endpoint that tells the truth about its
dependencies.

## Undo

Stop the API with `Ctrl+C`. The test entry stays in the database; `down -v` (lesson 1.2)
wipes it.
