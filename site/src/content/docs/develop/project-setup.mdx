## Goal

Create the project, with linting, type checks, a pinned Node version and an `.env.example`,
so the next lessons only add code.

## Steps

### 1. The layout

<Tabs syncKey="track">
<TabItem label="React + Hono">

Two parts, each with its own `package.json` and `node_modules`:

```
examples/react-hono-postgres/
  backend/    Hono API, Drizzle schema and migrations, .env.example
  frontend/   Vite + React app; imports the API contract from backend/
```

They are separate installs on purpose: in production they are separate things (static files
and one API container), and nothing has to be hoisted or shared at the root.

</TabItem>
<TabItem label="Next.js">

One Next.js app is both the frontend and the backend:

```
examples/nextjs-fullstack-postgres/
  src/app/         the page, the Server Action and the /api Route Handlers
  src/components/  the form, the list, the footer
  src/lib/         contract, env, logger, errors, rate limit, entries
  src/db/          Drizzle schema, migrate and seed scripts
  drizzle/         migrations (identical to the React + Hono track's)
```

It runs as one Node process in one container. The page, the form and the API share
`src/lib/` directly, so the contract needs no alias.

Steps 3 to 5 below show the React + Hono backend's files; this track's versions follow
the same rules:

<Code code={nextPackage} lang="json" title="package.json" />

- `dev` is `next dev`, which reads `.env` by itself; `pino-pretty` makes the JSON logs
  readable.
- `start` is `next start`. `db:migrate` and `db:seed` are plain Node scripts, the same as
  in the other track.

<Code code={nextTsconfig} lang="json" title="tsconfig.json" />

Next.js compiles the app itself, but the migrate and seed scripts run in Node directly and
import from `src/lib/`. So this track keeps the Hono backend's rules: `.ts` imports and
erasable syntax only. Next.js adds `allowJs`, `esModuleInterop` and its own `include`
entries on the first run; keep them.

<Code code={nextEnvExample} lang="sh" title=".env.example" />

There is no `PORT`: `next dev` and `next start` listen on 3000. The database URL says
`127.0.0.1`, not `localhost`; the comment says why.

```bash
cd examples/nextjs-fullstack-postgres
cp .env.example .env
```

</TabItem>
</Tabs>

### 2. Pin Node

The repo root has an `.nvmrc` with `22`, and every `package.json` says which Node it needs:

```json
"engines": { "node": ">=22.18" }
```

22.18 is the first Node 22 that runs TypeScript files directly, without a build step. The
backend relies on it.

### 3. The backend's `package.json`

<Code code={backendPackage} lang="json" title="backend/package.json" />

- `dev` runs `src/index.ts` directly, restarts on change (`--watch`) and reads `.env` if it
  exists. `pino-pretty` makes the JSON logs readable (lesson 1.7).
- `start` is what the container runs: no watch, no `.env` (the server passes real
  environment variables).
- `check` is what CI runs: types, then lint.

### 4. TypeScript without a build

<Code code={backendTsconfig} lang="json" title="backend/tsconfig.json" />

Node only *strips* types, it does not compile. So imports end in `.ts`, and syntax that needs
compiling (`enum`, `namespace`, constructor parameter properties) is an error
(`erasableSyntaxOnly`). `tsc` only checks types (`noEmit`).

### 5. `.env.example`

Every variable the backend reads, with a dev default and a comment. It is committed; your
own `.env` is not.

<Code code={envExample} lang="sh" title="backend/.env.example" />

```bash
cd examples/react-hono-postgres/backend
cp .env.example .env
```

The `.gitignore` at the root makes sure no other env file gets committed:

<Code code={gitignore.slice(gitignore.indexOf('# env files'))} lang="sh" title=".gitignore (end)" />

## Verify

<Tabs syncKey="track">
<TabItem label="React + Hono">

```bash
node -v                        # v22.18.0 or newer
cd examples/react-hono-postgres
npm --prefix backend run check
npm --prefix frontend run check
git status --short             # .env is not listed
```

Both checks finish without errors, and `git status` doesn't show `backend/.env`.

</TabItem>
<TabItem label="Next.js">

```bash
node -v                        # v22.18.0 or newer
cd examples/nextjs-fullstack-postgres
npm run check
git status --short             # .env is not listed
```

The check finishes without errors, and `git status` doesn't show `.env`.

</TabItem>
</Tabs>

From the repo root, `scripts/check.sh` runs every part's check in one go, and checks that
both tracks' `drizzle/` folders are identical.

## What you learned

A project you can come back to has its Node version, its checks and its configuration
written down: `.nvmrc` and `engines`, a `check` script, and an `.env.example` that lists
every variable. Secrets go in `.env`, which git ignores.

## Undo

Nothing on the server. Locally: `rm -rf */node_modules backend/.env` (React + Hono) or
`rm -rf node_modules .next .env` (Next.js).
