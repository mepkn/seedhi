## Goal

Every error has the same shape, and the UI shows loading, empty and error states with a
request ID a user can quote.

## Verify

With the API running:

```bash
curl -s localhost:3000/api/nope
# {"error":{"code":"NOT_FOUND","message":"Not found.","requestId":"…"}}

for i in 1 2 3 4 5 6; do
  curl -s -o /dev/null -w '%{http_code} ' -X POST localhost:3000/api/entries \
    -H 'content-type: application/json' -d '{"name":"R","message":"r"}'
done; echo
# 201 201 201 201 201 429   (fewer 201s if you posted in the last minute)
```

An unexpected error: stop Postgres, then ask for the entries.

```bash
docker compose -f ../../../infra/compose/dev.yml stop
curl -s -w ' %{http_code}\n' localhost:3000/api/entries
# {"error":{"code":"INTERNAL","message":"Something went wrong.","requestId":"42851e89-…"}} 500
```

The API's terminal shows `ERROR: unhandled error` with the same `requestId` and the real
cause. With the frontend running (lesson 1.8), reload the page now: the list shows the error
with `ref 42851e89-…` and a **Try again** button. Start Postgres again
(`docker compose … start --wait`) and press it: the entries load.

The empty state: on an empty database (`down -v`, then `npm run db:migrate`) the list says
"No entries yet. Be the first to sign."

## What you learned

Users get a short message and a reference; you get the full story in the logs under the same
reference. Expected errors are answered as they are; everything else is a 500 that reveals
nothing.

## Undo

Start Postgres again if you stopped it.
